# FP8 训练原理与实现

## FP8 训练概述

FP8 (8-bit floating point) 训练是降低大模型训练显存和计算开销的关键技术。相比 FP16/BF16，FP8 可将显存占用和计算带宽需求减半，使得在相同硬件资源上训练更大规模的模型成为可能。

## FP8 数据格式

> 昇腾 NPU 的完整数据类型体系请参见 [[concepts/ascend-data-types]]。

FP8 包含两种主要的数据格式，分别适用于训练的不同阶段：

| 格式 | 指数位 | 尾数位 | 适用场景 | 特点 |
|------|--------|--------|----------|------|
| **E4M3** | 4 bit | 3 bit | 前向计算（Forward） | 精度更高，动态范围较小 |
| **E5M2** | 5 bit | 2 bit | 反向计算（Backward） | 动态范围更大，精度较低 |

- **E4M3**：拥有 4 位指数和 3 位尾数，精度更高但表示范围有限，适合前向传播中的激活值和权重量化。
- **E5M2**：拥有 5 位指数和 2 位尾数，动态范围更大但精度较低，适合反向传播中梯度这类取值范围波动较大的数据。

## MX (Microscaling) 量化机制

MX (Microscaling) 是一种基于 block 的共享 scale 量化机制。其核心思想是将 tensor 划分为若干个 block，每个 block 内部共享一个 scale 值，从而减少量化所需的额外存储和计算开销。

MX 量化的主要优势：
- **降低量化开销**：共享 scale 减少了逐元素量化的计算量
- **减少显存占用**：scale 值的存储开销远小于独立量化
- **硬件友好**：block 级别的量化更适合 NPU 的并行计算架构

## Path A vs Path B 策略

### Path A

前向和反向都使用 **dual-axis 量化**（同时量化行和列），产生 4 个 tensor。这种策略的显存峰值较高，因为 dual-axis 量化会在瞬态分配大量中间缓冲区。

### Path B（默认推荐）

Path B 是当前推荐的优化路径，通过分轴量化策略避免显存峰值累积：

- **前向**：使用 col-only 量化（仅量化列）
- **反向**：使用 row-only 量化（仅量化行）

这种策略避免了 dual-axis 同时量化带来的瞬态显存分配叠加，从而有效降低训练过程中的显存峰值。

## 关键算子

FP8 训练中涉及以下关键 NPU 算子：

| 算子 | 功能 |
|------|------|
| `npu_dynamic_mx_quant(axis)` | 通用动态 MX 量化，通过 axis 参数指定量化轴 |
| `npu_dynamic_mx_quant_col_only` | 仅对列进行量化（Path B 前向使用） |
| `npu_dynamic_mx_quant_row_only` | 仅对行进行量化（Path B 反向使用） |
| `npu_dynamic_mx_quant_with_dual_axis` | 双轴量化（Path A 使用） |

## 与 DualPipe 的关系

在 [[concepts/dualpipe]] 场景下，FP8 量化算子的瞬态显存分配可能导致峰值累积。DualPipe 的流水线并行策略要求将计算和通信进行重叠，而 FP8 量化算子在执行过程中会动态分配临时缓冲区，这些临时缓冲区若与流水线中的其他显存分配同时存在，就会造成显存峰值叠加，进一步加剧 OOM 风险。

## 优化方向

针对 FP8 训练中的显存峰值问题，主要的优化方向包括：

- **预分配输出缓冲区**：在训练启动阶段预先分配好量化算子所需的输出缓冲区，避免运行时动态分配
- **复用显存**：通过显存池化技术，让不同算子复用同一块显存区域，减少总体显存占用
- **算子融合**：将量化算子与相邻计算算子融合，减少中间结果的显存驻留时间
