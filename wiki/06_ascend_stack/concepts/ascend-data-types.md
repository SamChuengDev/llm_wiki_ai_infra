# 昇腾 NPU 数据格式与类型

## 1. 数据类型

昇腾 NPU 支持以下数据类型：

| 类型 | 说明 |
|------|------|
| **float16** | 16 位半精度浮点，训练和推理中广泛使用 |
| **bfloat16** | 16 位脑浮点格式，与 float32 拥有相同的指数范围，精度较低但动态范围更大 |
| **float32** | 32 位单精度浮点，默认计算精度 |
| **float64** | 64 位双精度浮点，用于高精度需求场景 |
| **int8 / int16 / int32 / int64** | 有符号整数类型，覆盖 8 位到 64 位 |
| **bool** | 布尔类型 |
| **E4M3 / E5M2** | FP8 格式，详见 [[concepts/fp8-training]] |

## 2. 数据格式

昇腾 NPU 在内存中支持多种数据排布格式，不同格式对应不同的计算优化策略。

### 2.1 ND（N-Dimensional）

标准 N 维格式，与 PyTorch 默认的 row-major 连续内存排布一致。ND 格式是昇腾 NPU 的基础格式，所有算子均支持 ND 格式的输入输出。

### 2.2 NZ（Fractal）

NZ 格式（又称 Fractal 格式）是昇腾特有的分形格式，其核心思想是将矩阵划分为 16×16 的小块（fractal），并在内存中按块重新排列。这种格式的优点包括：

- **优化矩阵乘计算效率**：16×16 的分块大小与 NPU 的 Cube 计算单元匹配，可以充分利用硬件算力
- **减少显存访问**：分块后的数据局部性更好，cache 命中率更高
- **支持更大的矩阵运算**：分形格式可以高效处理超出单次硬件指令能力的矩阵运算

### 2.3 5D 格式

5 维格式是卷积运算专用的优化格式，本质上是 NCHW 格式的变形。通过将 NCHW 的维度重新排列为 5 个维度，使得卷积运算中的数据访问模式更适配 NPU 的向量计算单元。

### 2.4 TZ（Transpose）

TZ 是转置格式，用于存储矩阵转置后的数据，避免在运行时执行显式的转置操作。在需要频繁使用转置矩阵的场景（如反向传播）中，TZ 格式可以显著减少计算开销。

### 2.5 NCDHW

NCDHW 是 3D 卷积（3D Convolution）使用的数据格式，在 NCDHW 的基础上增加 Depth 维度，用于视频、医学影像等 3D 数据处理场景。

## 3. 格式转换

TorchNPU 提供了 `npu_format_cast` 算子用于在 ND 格式和其他格式之间进行转换。格式转换本身会引入额外的计算和显存开销，因此在设计网络时应尽量减少不必要的格式转换。

## 4. 量化数据格式

在 [[concepts/mx-quantization]] 机制中，MX 量化使用 block 共享 scale 的方式。其中：

- **scale 格式**：block 共享的 scale 值采用 FP8 格式存储
- **数据格式**：量化后的数据可以是 E4M3 或 E5M2 格式
- E4M3 精度更高但动态范围较小，适用于前向计算
- E5M2 动态范围更大但精度较低，适用于反向计算中的梯度量化

## 5. 性能影响

选择合适的数据格式对计算性能有显著影响：

- **ND 格式**：通用格式，适用于任意算子，但计算效率可能不是最优
- **NZ 格式**：矩阵乘场景下性能最优，推荐在矩阵密集的计算中使用
- **5D 格式**：卷积场景下性能最优，深度学习框架会自动进行格式转换
- **格式转换开销**：不同格式之间的转换需要额外的计算和显存带宽，频繁转换可能抵消格式带来的性能收益

在实际应用中，建议在性能关键路径上选择合适的格式，同时尽量减少格式转换的次数。
